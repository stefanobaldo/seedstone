Install

One line. Or any of five others.

Every way in; the binary is the same on each. The packages start a service on loopback. After Homebrew or Cargo, start the server with seedstone.

One line
curl -fsSL https://seedstone.io/install.sh | sh
macOS and Linux. Verifies the release's SHA-256, installs the binary, nothing else.
Container
docker run -p 6379:6379 seedstone/seedstone --bind 0.0.0.0:6379 --no-auth
Also on GHCR.
Homebrew
brew install seedstonelabs/tap/seedstone
macOS and Linux; as a service with brew services.
Cargo
cargo binstall seedstone
The release archive in seconds; cargo install builds from source.
Debian, Ubuntu / Fedora, RHEL
A .deb or .rpm with a systemd unit, from the release page; what the service does.
Kubernetes
helm install seedstone oci://ghcr.io/stefanobaldo/charts/seedstone --set auth.noAuth=true
The chart, and what auth.noAuth says.

(integer) 60
127.0.0.1:6379> get greeting
"hello"

Correct

The same seed, the same bug. Every time.

The whole server runs inside a deterministic simulation: a virtual clock, a simulated network, scheduled clients. Every completed command is folded into a trace hash that is a function of two seeds and nothing else, so a concurrency bug is reproduced from its seed, in a fresh process, byte for byte.

CI sweeps seeds on every code change, and proves the machinery on fourteen defects planted in the server itself: each has to be caught by the counter that owns it.

How it is built and how it is tested: docs/testing.md

Operated

Says only what it can state truthfully.

INFO in sections that carry only what the node can state truthfully; one JSON line per event; a password that rotates without a restart; a disk that fails or fills met with refusal, not with acknowledgements the node cannot keep. A stock Prometheus exporter scrapes it in CI.

Flags, output, signals, the password, persistence and INFO: docs/operations.md

Compatibility

A named list. Nothing answered approximately.

RESP2 over TCP, so redis-cli and the ordinary client libraries connect unmodified. The surface is a named list, chosen for the workloads this server targets: strings; keys and expiry; server; persistence. Anything outside the list is refused with an error naming the command, never answered approximately.

Not here yet: other data types, RESP3, replication, clustering, transactions, scripting. Next: hashes, lists, sets and sorted sets, Pub/Sub, RESP3.

Every command, every option, every refusal and every deliberate difference from Redis: docs/compatibility.md
