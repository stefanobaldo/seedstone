Install

One line. Or any of five others.

The binary is the same on every channel. The packages start a service on loopback; after Homebrew or Cargo, start it with seedstone.

curl

curl -fsSL https://seedstone.io/install.sh | sh

macOS and Linux, x86_64 and arm64. Verifies the release's SHA-256, installs the binary, nothing else.

Docker

docker run -p 6379:6379 seedstone/seedstone --bind 0.0.0.0:6379 --no-auth

Also on GHCR.

Homebrew

brew install seedstonelabs/tap/seedstone

macOS and Linux; as a service with brew services.

Cargo

cargo binstall seedstone

The release archive in seconds; cargo install builds from source.

deb / rpm

A .deb or .rpm with a systemd unit, from the release page; what the service does.

Helm

helm install seedstone oci://ghcr.io/stefanobaldo/charts/seedstone --set auth.noAuth=true

The chart, and what auth.noAuth says.

Correct

The same seed, the same bug. Every time.

The whole server runs inside a deterministic simulation: a virtual clock, a simulated network, scheduled clients. Every completed command folds into a trace hash that depends on two seeds and nothing else.

  1. seed 0x4f2a9c1e
  2. →
  3. virtual clock
  4. simulated network
  5. scheduled clients
  6. →
  7. trace 0x8b…31

A concurrency bug, the usual way no seed

  1. run 1✗ tick 6
  2. run 2passed
  3. run 3passed
  4. run 4✗ tick 9, elsewhere

Seen once, gone under the debugger, back in production.

In seedstone seed 0x4f2a9c1e

  1. run 1✗ tick 18 · 0x8b…31
  2. run 2✗ tick 18 · 0x8b…31
  3. run 3✗ tick 18 · 0x8b…31
  4. run 4✗ tick 18 · 0x8b…31

run 4 on another machine, in a fresh process

✓ Reproduced from the seed, byte for byte. Fixed once.

  • 14 / 14

    defects planted in the server itself, each caught by the counter that owns it

  • 2 seeds

    are all a trace hash depends on: the simulation's and the workload's

  • every change

    that touches code is swept across seeds in CI, and a failure arrives with its seed

Operated

Says only what it can state truthfully.

Built to be run by someone who is paged for it. A stock Prometheus exporter scrapes it in CI.

INFO, without the fiction

Sections that carry only what the node can state: no resident-set figure it would have to guess, no fork it does not have.

# Memory
maxmemory_policy:allkeys-lru
# Persistence
loading:0
aof_enabled:1
fsync_policy:interval
aof_last_write_status:ok
refusing_executors:0

One JSON line per event

Every line opens with a time, a level and the event's name; a monitor selects by evt and reads fields by name, with no parser of its own.

{"ts":1757800000000,"level":"info","evt":"listening","version":"0.1.1","bind":"0.0.0.0","port":6379}
{"ts":1757800000317,"level":"warn","evt":"error_reply","code":"ERR","cmd":"flushall","msg":"ERR unknown command 'flushall'"}

A password that rotates without a restart

Two passwords are valid while the file holds two, so the server and its clients never have to change in the same moment.

  1. 1add the new line, SIGHUP
  2. 2move the clients, any pace
  3. 3drop the old line, SIGHUP
{"ts":1757800003250,"level":"info","evt":"password_reloaded","passwords":2}

A disk that fails is met with refusal

A write the node cannot keep is not acknowledged: writes are refused until a snapshot is durable, reads are served, and a full disk asks for space, not for a restart.

# the disk is full, --fsync always
> SET order:9 paid
-MISCONF Errors writing to the log: writes are refused until a snapshot is durable
# space freed, a snapshot durable: refusal_ended
> SET order:9 paid
+OK

Flags, output, signals, the password, persistence and INFO: docs/operations.md
